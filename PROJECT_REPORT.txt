                            ABSTRACT
========================================================================

Urban traffic congestion is one of the most critical challenges faced
by modern cities, leading to economic loss, fuel wastage, and increased
road accidents. Traditional traffic monitoring systems rely on inductive
loop sensors and manual observation, which are expensive, inflexible,
and incapable of providing rich contextual data. This project presents
a Real-Time Smart Traffic Monitoring System that leverages deep learning
and computer vision to detect, classify, and count vehicles and
pedestrians from live camera feeds or recorded video.

The proposed system uses the YOLOv8 (You Only Look Once version 8)
single-stage object detection algorithm, pre-trained on the COCO dataset
containing 80 object classes. It detects vehicles (cars, trucks, buses,
motorcycles), pedestrians, bicycles, and traffic signals in real time.
A traffic density estimation module classifies scene congestion as
LOW, MEDIUM, or HIGH based on vehicle count thresholds.

The system produces annotated video output with bounding boxes and
a heads-up display (HUD), a session analytics report, and matplotlib
visualizations of detection statistics. Experimental results show
the system achieves 8–12 FPS on CPU and 60+ FPS on GPU (NVIDIA RTX
3060), making it suitable for practical deployment.

Keywords: YOLO, Object Detection, Traffic Monitoring, Deep Learning,
          Computer Vision, Convolutional Neural Networks, OpenCV.

1.1 Background
--------------
Traffic congestion costs the global economy billions of dollars annually
in lost productivity and fuel. In India alone, the Union Ministry of
Road Transport estimates that congestion costs ~$22 billion/year. Smart
traffic management is therefore a national priority.

Conventional monitoring approaches include:
  • Inductive loop detectors (expensive, point-level data only)
  • CCTV with manual observation (human error-prone, expensive)
  • Radar/LIDAR sensors (very costly, complex installation)

Computer vision + deep learning offers a cost-effective alternative:
existing camera infrastructure can be repurposed with AI software for
continuous, automated, granular traffic analysis.

1.2 Problem Statement
---------------------
Design and implement a software system that:
  (a) Takes a video stream as input (live or recorded)
  (b) Detects and classifies traffic objects in each frame
  (c) Counts vehicles and pedestrians per frame
  (d) Estimates traffic density (Low / Medium / High)
  (e) Outputs annotated video + analytics charts

1.3 Objectives
--------------
  • Implement real-time object detection using YOLOv8
  • Detect cars, trucks, buses, motorcycles, pedestrians, bicycles
  • Estimate per-frame traffic density
  • Generate a session analytics report and visualizations
  • Build a clean, modular, beginner-friendly codebase

1.4 Scope
---------
The system operates on any video source (file, webcam, IP camera).
It does not perform tracking (object IDs across frames) or signal
control in this version — those are identified as future work.

                        2. LITERATURE SURVEY
========================================================================

2.1 Traditional Methods
-----------------------
Early traffic counting relied on pneumatic tubes and loop sensors
(Klein, 2006). These provide volume and speed data but no visual
classification. Manual video review (Traffic Analysis, 2005) is
labour-intensive and suffers from observer fatigue.

2.2 Classical Computer Vision
------------------------------
Background subtraction (Stauffer & Grimson, 1999), optical flow
(Lucas-Kanade, 1981), and HOG+SVM (Dalal & Triggs, 2005) were widely
used for vehicle detection. They are sensitive to lighting changes
and scene complexity.

2.3 Deep Learning Approaches
-----------------------------
  • R-CNN family (Girshick et al., 2014) – two-stage detectors with high
    accuracy but low speed (~5 FPS on GPU).
  • SSD (Liu et al., 2016) – single-shot, ~59 FPS, lower accuracy.
  • YOLOv1–v5 (Redmon et al., 2016–2020) – progressive improvements in
    speed/accuracy trade-off.
  • YOLOv8 (Ultralytics, 2023) – state-of-the-art, anchor-free head,
    C2f backbone, 50+ mAP on COCO at 160+ FPS (nano model).

2.4 Traffic-Specific Deep Learning
------------------------------------
  • Luvizon et al. (2016) used CNN for vehicle counting from drone images.
  • Hasan et al. (2020) applied YOLO for real-time highway monitoring.
  • Mandal et al. (2022) combined YOLO + DeepSORT for vehicle tracking.

Our system builds on the YOLOv8 backbone with a custom density
estimation layer, targeting deployability on inexpensive CPUs.

                          3. METHODOLOGY
========================================================================

3.1 YOLO Algorithm
------------------
YOLO (You Only Look Once) is a single-stage real-time object detection
framework. Unlike two-stage detectors (R-CNN) that first propose regions
then classify them, YOLO treats detection as a single regression problem.

Key concepts:
  • The image is divided into an S×S grid (e.g., 20×20 for a 640×640 image)
  • Each grid cell predicts B bounding boxes and C class probabilities
  • Output: confidence score = P(object) × IoU(pred, truth)
  • Non-Maximum Suppression (NMS) removes duplicate boxes

YOLOv8 improvements over prior versions:
  • Anchor-free detection head (no predefined anchor boxes)
  • C2f (Cross-Stage Partial with 2 convolutions) backbone
  • Decoupled classification and regression heads
  • CIoU / DFLoss objective function

3.2 Model Variants
------------------
  Variant | Params  | mAP50 (COCO) | Speed (CPU)
  yolov8n | 3.2 M   | 37.3         | 80 ms/frame
  yolov8s | 11.2 M  | 44.9         | 128 ms/frame
  yolov8m | 25.9 M  | 50.2         | 234 ms/frame
  yolov8l | 43.7 M  | 52.9         | 375 ms/frame

We use yolov8n (nano) for maximum speed, with easy swap to larger models.

3.3 COCO Dataset
----------------
The COCO (Common Objects in Context) dataset contains 118K training
images with 80 class annotations. Traffic-relevant classes:
  Class 0  – Person
  Class 1  – Bicycle
  Class 2  – Car
  Class 3  – Motorcycle
  Class 5  – Bus
  Class 7  – Truck
  Class 9  – Traffic Light

No additional training is required; the pretrained weights generalise
well to traffic scenes.

3.4 Traffic Density Estimation
--------------------------------
The density module counts vehicles per frame and applies thresholds:
  • ≤ 5 vehicles  → LOW    (green)
  • 6–15 vehicles → MEDIUM (orange)
  • > 15 vehicles → HIGH   (red)

Thresholds are configurable in src/config.py.

3.5 Inference Pipeline
-----------------------
  Input Frame
    │
    ▼
  Resize to 640×640 (letterbox pad)
    │
    ▼
  YOLOv8 Forward Pass (backbone + neck + head)
    │
    ▼
  Decode predictions (cx,cy,w,h,conf,cls)
    │
    ▼
  Filter by conf≥0.40  →  NMS (IoU≤0.45)
    │
    ▼
  Class filter (vehicles + pedestrians only)
    │
    ▼
  Count vehicles → Density label
    │
    ▼
  Annotate frame (boxes + HUD)
    │
    ▼
  Write to output video + CSV log

    • annotate()   : draws boxes + HUD on frame; returns annotated copy

  src/visualizer.py
    • plot_class_distribution() : bar chart of detected classes

========================================================================

                         8. LIMITATIONS
========================================================================

  1. No Object Tracking
     Vehicles are re-detected each frame; no persistent ID means
     double-counting is possible for stationary vehicles.

  2. Occlusion Sensitivity
     Heavily overlapping vehicles may be missed or merged.

  3. Small Object Performance
     Motorcycles and distant pedestrians have lower recall.

  4. Fixed Density Thresholds
     Thresholds are global; a two-lane road and six-lane highway
     need different calibration.

  5. Night / Adverse Weather
     Performance degrades without additional lighting enhancement
     or domain-adapted fine-tuning.

  6. No Signal Control Integration
     The system only monitors; it does not actuate any signals.
